DIRECTION 方向性

この道具がどうありたいか

白と青で、すっきり。ギター弾きが弾きながら一瞬で読める見やすさを土台に、 無彩色の灰を1つも使わない。 色を持つ場所は帯・主操作・度数の点だけに決めて、それ以外は白と紺で静かに整える。
参照点: Flat（楽譜アプリ）／弾きながら見るコード譜サイト／明るいまま詰まった音楽アプリ

3つの柱

見やすい

弾きながら視線を落として一瞬で読める。小さい灰色の文字で埋めない。本文と数値は AA を満たす。主役は大きく、脇役は小さく退く。

白と青

地はほぼ白、面は白。濃い面は帯だけ。青は1色で、決まった場所にしか出ない。淡い青を面積で塗り広げない。

灰を殺す

黒も灰もすべて紺を含ませる。#9A9A9A のような無彩色を1つも残さない。ここが効く。

いま何が問題だったか（実測）

計測現状この仕様書で目指すもの
文字色180要素中 144が灰色主役は --navy-1。灰（紺の薄い段）は脇役だけ
灰色の質#9A9A9A 系の無彩色青を含む紺の4段に置き換える。無彩色を1つも残さない

指板1px の灰色の格子白い面＋紺の罫。色が乗るのは点だけ。この道具の主役

なぜ白と青にしたか

先にくすんだ陶器色の案を作って捨てた。淡い色を面積で塗ると、狙った「味」ではなく「ぼんやり」になる。 参照した Flat から実測して分かったのは、あのすっきりが青のおかげではないということだった。効いているのは4つで、どれも色相の話ではない。

効いているもの実測
無彩色が1つも無い文字 #1C264C は黒ではなく紺。副文 #606782 は灰ではなく青灰
地に色がついている地 #F3F7FE は白ではなく青みのほぼ白。その上に純白のカードが乗る
青は薄めない#1566EE。淡い青は下地にしか使わず、文字や線には使わない
太さの差が大きい見出しは 700。本文との差が形で分かる

AI が作ったように見える原因は「淡い・無彩色・全部同じ太さ」であって、色相ではない。 だから陶器をやめて白と青にしても、守る規律は同じものになる。

AGENT RULES 実装前に読む

UIを作る・変える前に

必ず守る

  • 色・文字・余白・角丸・境界は 既存のCSS変数から選ぶ。生の値を新しく書かない
  • 無彩色を書かない。#888 gray #333 は禁止。灰が要るなら --navy-3 / --navy-4
  • 度数の色（--c-*）はデータ専用。UIの装飾に絶対に使わない
  • 逆も禁止。青（--blue）を、度数の点が出る面の中に持ち込まない。指板とカードの中に青いUIを置かない
  • ぼかし影を使わない。白い面は 1px の罫で浮かせる
  • 主操作＝青の塗り／補助＝白に罫／静かな操作＝青の文字。3つを混ぜない
  • 空・1件・大量・エラー・読み込み中を必ず設計する
  • デザインを変えたら この DESIGN.html も同じコミットで更新する

重要度の付け方

この順で強くする。色は最後の手段。

  1. 文字の大きさ
  2. 文字の太さ（400 → 700）
  3. 文字の濃さ（--navy-1 〜 --navy-4）
  4. 余白（近づける／離す）
  5. 面を変える（地 → 白 → 溝）
  6. 罫を足す
  7. 青を使う

憲法の改訂が要る変更

この仕様書は現行 CLAUDE.md と3点で食い違う。黙って寄せず、先に改訂すること。

  • §3「太さは 400 と 500 だけ」→ 見出しに 700 を解禁
  • §3「角丸は --r(6px)」→ 8px と 14px の2段
  • §3「文字サイズの表」→ 46px / 26px / 22px を追加、10px と 7px を廃止

廃止するサイズ: 10px と 7px。実測で 116要素がここに集中していた。
唯一の例外は「点の中」。指板の音名とカードの指番号だけは 10px / 700 を許す。 塗りつぶした円の上に太字で乗る文字は、地の上の 10px とは別物だから。 点の外に 11px 未満を置かない。これで 9px・7px の逃げ道を塞ぐ。

太さは 400 と 700 の2つだけ。500 と 600 は作らない——中間があると「なんとなく太い」が増えて段差が消える。 現行の 500 はすべて 700 か 400 のどちらかに寄せる。

SPACE 余白・角丸・罫・影

厚みは影ではなく罫で出す

余白

4px 刻み。近いものは --s2、群の間は --s5、セクションの間は --s7〜8。 同じ値を並べない——群の中は詰め、群の間は開ける。

角丸

現行の 6px より大きくする。--r 8px（部品）と --r-lg 14px（面）の2段だけ。円は 50%。 ピル形は使わない——SaaS風のタグに寄るため。

8px 部品
14px 面
ピル

罫

1px --line が基本。面の中の区切りは --line-soft。 2px は選択状態にだけ使う（タブの下線＝青、カードの縁＝紺）。

影

box-shadow は1つも使わない。 地がほぼ白なので、段差は「上」ではなく「下」に取る——浮かせるのではなく、へこませる。 浮いている要素（サジェスト、ポップオーバー、下部バー）は白い面のまま、1pxの罫だけで持ち上げる。

浮いている面：白＋罫だけ
へこんだ面：溝＋罫。非選択・空状態

実装は色ごとの分岐ではなく、点の色に対応づけた1つの表で持つ。 度数色を足したらこの表にも1行足す——足し忘れれば読めない点ができる。

色だけに依存しない

  • 度数は色に加えて凡例の文字で示す。色覚に依存しない
  • 選択中のタブは色 + 太さ + 下線の3つで示す
  • ミュートは色ではなく × の形で示す
  • いま指板に出ているカードは色ではなく縁の太さで示す

その他

  • フォーカスは罫の色を --blue に変えて示す。outline:none だけにしない
  • SVG の要素を操作対象にするときは role="button" tabindex="0" と Enter/Space を自前で配線する
  • 開閉する要素には aria-expanded
  • prefers-reduced-motion:reduce で .12s のトランジションとスクロールを無効化する
KNOWN GAPS 未定義

まだ決まっていないこと

決めてほしい

  • エラーの赤。青でも紺でもない色をもう1つ入れることになる。度数の Root（レンガ色）と紛らわしくないか、実機で見たい
  • 下部バー（#mini）の面。白だと地と同化し、溝だと沈む。濃青の細い帯が候補だが、帯が画面に2本になる
  • 濃青の帯を上部に置くか。この仕様書では置いている。置かないなら青は主操作とリンクだけになり、かなり静かになる

検討して決めたこと

  • くすんだ陶器色の案は捨てた。淡い色を面積で塗ると「味」ではなく「ぼんやり」になる
  • 地はほぼ白のまま、ただし無彩色ではなく #F3F7FE（青みのほぼ白）
  • コード名は明朝にしない。書体は1つのまま
  • 青と度数色の衝突は、色ではなく場所で解く。指板とカードの中に青を入れない
  • 点の中の白い音名がコントラスト不足だった。薄い3色は紺にする、tension は深める
